# Saving a reply preference on purpose

When an organizer repeatedly asks for bullet points, it is reasonable
to let them save that choice once. Keeping every sentence that sounds
like a preference would also save things that only apply to one
workshop or contain someone else's information.

The memory panel offers a small set of choices for list format, level
of detail and tone. Each president can save one value per kind in the
selected workspace. Core stores the choice, the owner and the time.
A repeated save of the same value returns the original entry. An
attempt to save a different value over it needs another deliberate
operation. The separate Remove action hard-deletes the entry.

The scope uses both the owner and the organization. The same
president's other workspace starts with its own empty memory.
A successor cannot see or reuse the previous president's preferences.
Those checks use the current Campusly role.

The stored choices provide a boundary for later recall. It is worth
keeping the first version this small. We can test what is allowed
without depending on a model's ability to detect sensitive free text.
